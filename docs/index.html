Miso TTS 8B · Apple Silicon Port

An 8B text-to-speech model, running entirely on a Mac.

MisoTTS is a Sesame-CSM-style 8-billion-parameter speech model that shipped CUDA-only. This fork ports it to Apple Silicon via MLX — validated against the original CUDA model at the logit level, with a lossless ~2× real-time mode and voice cloning.

What it is

Two transformers (a Llama-3.2-style 8B backbone + a 300M depth decoder) generating Kyutai Mimi codes at 12.5 Hz, decoded to 24 kHz audio. The upstream code selects CUDA or CPU and explicitly skips Metal ("float64 limitations"). This fork adds a PyTorch/MPS path for correctness and a native MLX path for speed — the MLX model reuses mlx_lm's LlamaModel with a torchtune-convention RoPE, so the checkpoint loads with no weight permutation.

Quickstart (CLI)

One-time setup, then run from the checkout (the model — ~33 GB — downloads once):

git clone https://github.com/geniusyinka/MisoTTS.git
cd MisoTTS
uv sync --python 3.10
uv pip install -r requirements-mlx.txt

# generate (Q8 = lossless, recommended)
uv run python run_misotts_mlx.py --text "Hey, this is running on my Mac." --bits 8 --out out.wav
afplay out.wav

First run loads the model (~60 s), then generates. The watermark is applied by default; the MLX path needs no Hugging Face token (ungated tokenizer + public Mimi codec).

RTF = compute ÷ audio seconds (M4 Pro, 64 GB). RTF > 1 means slower than real-time. fp16 is intentionally unused — it's slower at batch=1.

Voice cloning

Pass a reference clip to speak in that voice (give its transcript for best results):

uv run python run_misotts_mlx.py --bits 8 \
  --ref-audio jane.wav --ref-text "what jane says in jane.wav" \
  --text "This line is spoken in Jane's voice." --out jane.wav

Identity is anchored by the reference (stable run to run; pitch/energy still vary take to take). A bare --speaker id is only a turn marker, not a fixed identity.

How we know it's correct

Generation is stochastic, so we validate on deterministic logits — three independent pillars:

01

Frame-0 gate

Single forward vs the CUDA reference: cosine 0.9999, top-1 match. The bug-catcher (RoPE, weight layout).

02

1,117-frame trace

Teacher-forced full utterances (5 styles, two 30s+). fp32 & Q8 hold cosine 0.9999 / ~99% top-1, no drift over long context. Q8 is lossless.

03

Voice identity

5 voice-cloned characters: cross-backend speaker similarity (0.882) equals a backend's own take-to-take variation (0.886) — a cloned voice is the same person on MLX as on CUDA.

From a web UI

A separate Next.js + FastAPI app drives the model. It defaults to a mock engine (instant, no model); set MISO_ENGINE=mlx for real generation.

# backend (terminal 1)
cd misotts-mlx-web/server
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
MISO_ENGINE=mlx uvicorn app.main:app --port 8000        # mock: omit MISO_ENGINE

# frontend (terminal 2)
cd misotts-mlx-web && npm install && npm run dev        # http://localhost:3000
Note: the real-MLX web path shells out per request, so each clip reloads the model (~60 s) before generating. For snappy repeated use, prefer the CLI (same engine, no reload) — a persistent warm-model server is a future improvement.

Gotchas

  • The fp32 checkpoint is 32 GB — loading it the stock way peaks ~64 GB RAM and OOMs a 62 GB box; load GPU-direct in bf16, streaming weights one tensor at a time.
  • Don't quantize everything to Q4 — it breaks codebook-1 logits. Use --quant mixed (backbone Q4, decoder/heads Q8, embeddings fp) or --bits 8.
  • moshi_mlx pins an old mlx and breaks mlx-lm; use mlx-audio's Mimi instead.
  • If Hugging Face downloads stall behind a VPN/zero-trust client, fully quit it for the one-time model pull.
